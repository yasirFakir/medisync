# document.md

> **Purpose**
>
> Create or update project documentation that is clear, concise, and synchronized with the implementation.

## Objective

Document the project—not opinions.

Documentation should reflect the current state of the codebase.

---

## Rules

* Write for future developers.
* Be concise.
* Keep documentation consistent.
* Update existing docs before creating new ones.
* Avoid duplication.
* Use Markdown.
* Include examples only when they improve understanding.

---

## Documentation Priority

Update in this order:

1. README
2. TASK
3. ADR
4. Architecture
5. Engineering Guides
6. API Documentation

Only update documents affected by the change.

---

## Deliver

Summarize:

* Documents updated
* New documents created
* Important changes

---

## Success Criteria

Documentation accurately reflects the implementation, is easy to navigate, and requires minimal maintenance.
